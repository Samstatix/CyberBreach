# External Research and Reference Policy

CyberBreach may study public educational resources, standards and tools to improve its curriculum and challenge quality. External platforms are references for pedagogy and technical accuracy, not sources to copy or republish proprietary content.

## Reference platforms and standards

| Reference | Appropriate use in CyberBreach | Boundary |
|---|---|---|
| TryHackMe | Study beginner-friendly learning paths, room sequencing, guided practice and interactive explanations. | Do not copy paid room text, task answers, flags, walkthroughs or downloadable challenge assets. |
| Hack The Box Academy | Study modular technical training, skill progression, practical checkpoints and assessment design. | Do not reproduce proprietary modules, machines, flags, walkthroughs or challenge files. |
| PortSwigger Web Security Academy | Technical reference for web vulnerabilities and authorized practice-lab patterns. | Create original explanations and platform-owned/authorized targets. |
| OWASP Web Security Testing Guide | Methodology and test coverage for web application security education. | Attribute source material and respect the relevant license when reusing text or assets. |
| NIST NICE Framework | Map learning outcomes to cybersecurity work roles, tasks, knowledge and skills. | Use as a competency reference, not as a certification claim. |
| MITRE ATT&CK | Organize adversary behavior concepts and defensive detection exercises. | Keep exercises fictional and authorized; cite version and source when mapping content. |

## Research workflow

For every external reference used to design a module or challenge, record:

- Resource name and canonical URL.
- Date accessed and version/edition where applicable.
- The specific concept, method or learning design studied.
- What CyberBreach authored independently.
- License and attribution requirements for any reused material.
- Reviewer and last technical validation date.

## Original-content requirement

CyberBreach challenge descriptions, flags, storylines, hints, solution walkthroughs, datasets and lab images should be original, CollabCircle-owned, or explicitly licensed for the intended use. A public webpage is not automatically permission to copy its content.

When an external source is used for factual technical claims, link and cite it in the relevant lesson. Distinguish source-derived facts from CollabCircle's own examples and analysis.

## Technical validation

Challenge authors and reviewers must reproduce the intended solution in the documented environment. Check alternative valid solutions, reset behavior, expected output, safety boundaries and defensive lessons. Do not publish a challenge solely because its idea appears in another platform.
