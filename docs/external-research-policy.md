# External Research and Reference Policy

CyberBreach may study public educational resources, standards and tools to improve curriculum and challenge quality. External platforms are references for pedagogy and technical accuracy, not sources to copy or republish proprietary content.

## Reference library

| Reference | Appropriate use | Boundary |
|---|---|---|
| [TryHackMe Pre Security](https://tryhackme.com/path/outline/beginner) | Study a beginner progression from computer fundamentals through networking and web basics. | Do not copy room text, task answers, flags, walkthroughs or downloadable challenge assets. |
| [TryHackMe Cyber Security 101](https://tryhackme.com/path/outline/cybersecurity101) | Study how a broad foundation path connects Linux, Windows, networking, cryptography and defensive/offensive topics. | Link learners to the provider; author CyberBreach explanations and evidence independently. |
| [Hack The Box Academy paths](https://academy.hackthebox.com/catalogue/paths) | Study modular sections, skill paths, assessment structure and role-based progression. | Do not reproduce proprietary modules, machines, flags, walkthroughs or challenge files. |
| [PortSwigger Web Security Academy](https://portswigger.net/web-security/) | Technical reference for web vulnerabilities and interactive authorized practice labs. | Use original CyberBreach examples or authorized provider labs; do not republish their lab content. |
| [OWASP Web Security Testing Guide](https://owasp.org/projects/web-security-testing-guide) | Methodology and coverage for web application security testing. | Attribute and follow the project's applicable license for any reused material. |
| [OWASP GenAI LLM Top 10 (2026)](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/) | Current risk taxonomy and mitigation research for LLM applications. | Summarize in original language and link to the canonical publication. |
| [MITRE ATLAS](https://atlas.mitre.org/) | Organize AI-system adversary tactics, techniques and case studies. | Use as a framework reference; cite the version or access date where relevant. |
| [NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) | Risk-management concepts for AI system design, deployment and use. | Do not claim certification or endorsement. |

## Research workflow
For every external reference used to design a module or challenge, record:
- Resource name and canonical URL.
- Date accessed and version/edition where applicable.
- The concept, method or learning design studied.
- What CyberBreach authored independently.
- License and attribution requirements for any reused material.
- Reviewer and last technical validation date.

## Original-content requirement
CyberBreach challenge descriptions, flags, storylines, hints, solution walkthroughs, datasets and lab images must be original, CollabCircle-owned, or explicitly licensed for the intended use. A public webpage is not automatically permission to copy its content.

Do not scrape or republish paid course content. Link users to the provider's official page and let that provider enforce its own account and access model.

## Technical validation
Challenge authors and reviewers must reproduce the intended solution in the documented environment. Check alternative valid solutions, reset behavior, expected output, safety boundaries and defensive lessons. No challenge should direct learners to attack real third-party systems or investigate private individuals.
